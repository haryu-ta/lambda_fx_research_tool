# 機能仕様: 為替レート LINE 通知

**Feature Branch**: `001-create-feature-branch`

**Created**: 2026-05-16

**Status**: Draft

## ユーザーシナリオとテスト *(mandatory)*

### ユーザーストーリー 1 - 定期実行された USD/JPY 通知を受け取る (Priority: P1)

エンドユーザーとして、最新の USD/JPY レートを定期メッセージで受け取りたい。そうすることで、別アプリを開かずに相場を素早く確認できる。

**Why this priority**: この機能がプロダクトの中核価値であり、最小実用価値を成立させるため。

**Independent Test**: 1つのスケジュールを設定し、要求フォーマットと時刻を満たす通知が1件配信されることを確認する。

**Acceptance Scenarios**:

1. **Given** 有効なスケジュール設定と外部サービス認証情報がある、**When** 定期実行タイミングになる、**Then** ユーザーへ「HH:MM時点  1ドル = XXX.XX 円」形式のメッセージが届く。
2. **Given** 為替レート取得が成功している、**When** 通知を送信する、**Then** 通知内の USD/JPY 値は取得値を小数第2位で表示した値と一致する。

---

### ユーザーストーリー 2 - 外部 API 障害時に安全運用できる (Priority: P2)

運用者として、障害を明確に可視化したい。そうすることで、連携障害を迅速に検知して対処できる。

**Why this priority**: 本番では外部サービス障害が発生し得るため、通知品質への信頼維持に障害検知性が必須となる。

**Independent Test**: 為替 API エラーを発生させ、構造化エラーログが出力されることに加えて、ユーザーへ「HH:MM時点  為替API　実行NG」通知が送信されることを確認する。

**Acceptance Scenarios**:

1. **Given** 為替レート提供元が利用不可である、**When** 定期実行が走る、**Then** 構造化エラーログが記録され、ユーザーへ「HH:MM時点  為替API　実行NG」が送信され、実行は失敗終了する。
2. **Given** 通知配信呼び出しが失敗する、**When** 定期実行が走る、**Then** 構造化エラーログが記録され、実行は失敗終了する。

---

### ユーザーストーリー 3 - JST 基準で実行時刻を制御できる (Priority: P3)

運用者として、cron と JST で実行時刻を設定したい。そうすることで、想定した業務時間帯に通知を配信できる。

**Why this priority**: スケジュール柔軟性は重要だが、通知自体の成立より優先度は低い。

**Independent Test**: cron スケジュールと JST を設定し、意図した JST 時刻にのみ通知がトリガーされることを確認する。

**Acceptance Scenarios**:

1. **Given** 有効な cron 式と JST タイムゾーン設定がある、**When** 指定時刻になる、**Then** 期待した JST 時刻に実行される。

### エッジケース

- 為替レスポンス自体は成功だが、有効な USD/JPY 数値が含まれない場合は、ユーザーへ「HH:MM時点  為替情報取得できず」を通知し、実行は失敗終了する。
- 一時的なレート制限やスロットリング応答を受けた場合は、リトライせず、ユーザーへ「HH:MM時点  為替API　実行NG」を通知し、実行は失敗終了する。
- 実行時に認証情報が未設定または空文字だった場合は、ユーザーへ「HH:MM時点  為替情報取得NG」を通知し、実行は失敗終了する。
- メッセージ送信完了直前のタイムアウトが発生した場合は、重複配信を防ぐため再実行しない（自動リトライを無効化する）。その代わり当該回の通知欠損は許容し、ERROR ログで検知可能にする。

## 要件 *(mandatory)*

### 機能要件

- **FR-001**: システムは、設定可能な定期スケジュールで自動実行しなければならない。
- **FR-002**: システムは、無料プラン互換の外部プロバイダーから最新の USD/JPY レートを取得しなければならない。
- **FR-003**: システムは、通知文面を「HH:MM時点  1ドル = XXX.XX 円」の形式で生成しなければならない。
- **FR-004**: システムは、設定された LINE の通知対象へメッセージを配信しなければならない。
- **FR-005**: システムは、成功実行時に実行時刻と配信結果を含む構造化 INFO ログを記録しなければならない。
- **FR-006**: システムは、外部プロバイダー障害および配信障害時に構造化 ERROR ログを記録しなければならない。
- **FR-007**: システムは、為替取得または通知配信が失敗した場合、実行を失敗終了しなければならない。
- **FR-008**: システムは、すべてのシークレットと認証情報を環境設定から読み込み、ソースへハードコードしてはならない。
- **FR-009**: システムは、JST のタイムゾーン挙動を前提とした cron 式スケジュール定義をサポートしなければならない。
- **FR-010**: システムは、JSON 形式の為替レスポンスを処理しなければならない。
- **FR-011**: システムは、為替 API 実行失敗時に LINE へ「HH:MM時点  為替API　実行NG」のエラー通知を送信しなければならない。
- **FR-012**: システムは、為替レスポンスに有効な USD/JPY 数値が含まれない場合、LINE へ「HH:MM時点  為替情報取得できず」の通知を送信し、実行を失敗終了しなければならない。
- **FR-013**: システムは、為替 API のレート制限またはスロットリング応答を受けた場合、リトライせず、LINE へ「HH:MM時点  為替API　実行NG」の通知を送信して実行を失敗終了しなければならない。
- **FR-014**: システムは、実行時に必要な認証情報が未設定または空文字である場合、LINE へ「HH:MM時点  為替情報取得NG」の通知を送信し、実行を失敗終了しなければならない。
- **FR-015**: システムは、スケジュール起動経路において自動再実行を行わない設定とし、通知送信タイムアウト時に同一実行の再試行による重複配信を発生させてはならない。

### 主要エンティティ *(include if feature involves data)*

- **スケジュール設定**: cron 式とタイムゾーン文脈を含む定期実行ルール定義。
- **為替レートスナップショット**: 取得時刻、USD/JPY 数値、提供元応答状態を持つ時点データ。
- **通知メッセージ**: 表示時刻と小数第2位までのレート値を含む配信用テキスト。
- **実行ログレコード**: レベル、実行時刻、連携先状態、必要時のエラー詳細を含む構造化運用イベント。

## 成功基準 *(mandatory)*

### 測定可能な成果

- **SC-001**: 30日間の定期実行のうち 99% で、依存先が正常な場合にユーザー通知がちょうど1件生成される。
- **SC-002**: 成功実行の 95% で、トリガー時刻から 60 秒以内に通知配信が完了する。
- **SC-003**: 外部連携失敗の 100% で、時刻・失敗連携先・失敗理由を含むエラーログが記録される。
- **SC-004**: 本番通知の 100% が、時刻表示と小数第2位のレート表示を含む指定フォーマットに一致する。
- **SC-005**: 為替 API 実行失敗の 100% で、5分以内に「HH:MM時点  為替API　実行NG」形式のエラー通知が1件配信される。

## 前提

- 対象ユーザーは USD/JPY を定期確認したい受信者であり、双方向応答機能は不要とする。
- 初期リリースでは通知先は 1 宛先で十分とし、複数宛先配信はスコープ外とする。
- リトライ/復旧方針は、別途明示がない限りプラットフォーム既定の挙動に従う。
- 採用する無料プランの為替 API は、想定実行頻度に対して十分な利用枠を提供する。
